# Русский Ясно v24 — облачная синхронизация

## Что реализовано в клиенте
- Email/password signup and login через Supabase Auth REST API.
- Refresh access token через refresh token.
- Cloud profile в таблице `public.user_progress`.
- Автоматическая отправка локального профиля после изменений с debounce 1.4 секунды.
- Загрузка облачной копии при первом входе на устройство с подтверждением выбора.
- Выход из облачного аккаунта на устройстве.
- При потере интернета локальные данные продолжают сохраняться; синхронизация возобновляется при восстановлении подключения.
- Конфигурация берётся из `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`; секретный service_role key не используется.
- Добавлена SQL-схема с RLS, ограничивающая SELECT/INSERT/UPDATE строкой текущего `auth.uid()`.
- GitHub Actions получает конфигурацию из Repository Secrets.

## Что должен сделать владелец проекта
1. Создать собственный Supabase project.
2. Выполнить `supabase/schema.sql` в SQL Editor.
3. Настроить Email Auth и Redirect URLs.
4. Добавить `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в GitHub Repository Secrets.
5. Опубликовать обновлённый проект.

До выполнения этих шагов интерфейс явно сообщает, что облако не настроено. Рабочая синхронизация не может быть активирована без проекта и его конфигурации.

## Разрешение конфликтов
При входе, если облачная копия уже есть, приложение спрашивает: загрузить облако на устройство или заменить облачную запись текущим локальным профилем. После входа используется last-write-wins для всего JSON-профиля с задержкой 1.4 секунды. Одновременное редактирование одного профиля на нескольких устройствах может привести к перезаписи более раннего сохранения; это ограничение показано в интерфейсе.

## Безопасность
- Используется только публичный anon/publishable key на клиенте.
- service_role key не нужен и не должен попадать в frontend или GitHub Pages build.
- Доступ к строкам ограничен Row Level Security.
- В клиенте сохраняются access/refresh tokens для поддержания сессии.
- Данные профиля, включая аватар, передаются в Supabase после авторизации.
- Рекомендуется включить подтверждение email и настроить Redirect URLs.
- Для production-уровня дополнительно рекомендуется настроить CAPTCHA/rate limits и проверить политики проекта.
