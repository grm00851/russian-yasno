# Русский Ясно — технический аудит v22

Дата проверки: 03.11.2026

## Итог

Предварительная оценка исходного проекта: **8,0/10**. Это оценка качества структуры и реализованных функций по статическому просмотру исходников, а не результат полноценного нагрузочного, браузерного или penetration-тестирования.

## Что проверено

- Архив распаковывается без ошибок; в исходном архиве 33 файла.
- Проверены конфигурации React/Vite/TypeScript, GitHub Actions, PWA manifest, Service Worker, HTML meta/CSP, главные файлы приложения, CSS и структура учебных банков.
- Поиск по исходникам не обнаружил `dangerouslySetInnerHTML`, присваиваний `innerHTML`, `eval()` или `new Function()`.
- Внешние ссылки, открываемые в новой вкладке, используют `rel="noreferrer"`.
- Прогресс хранится в localStorage; чтение JSON защищено `try/catch`, данные проходят нормализацию.
- Файлы изображений ограничены JPG/PNG/WEBP и 12 МБ; аватар уменьшается на клиенте перед сохранением.
- Для временного URL изображения предусмотрено освобождение через `URL.revokeObjectURL`.
- Для OCR используется отдельный worker, который завершается после распознавания.
- В CSS есть адаптивные точки для широких экранов, планшетов и телефонов, а также `prefers-reduced-motion`.
- Проверены наличие ARIA-атрибутов и семантических элементов в интерфейсе.

## Исправлено в аудиторской редакции

- Повышена версия кеша Service Worker с v9 до v10. Это заставляет PWA создать новый кеш и удалить старые кеши с тем же префиксом при активации, чтобы обновлённые файлы не оставались скрытыми за старым кешем.

## Замечания и ограничения

1. **Сборка не подтверждена.** `npm run build` остановился на отсутствующих локальных типах `vite/client` и `node`. Установка зависимостей (`npm ci`) не завершилась в доступное время. `npm run lint` не запустился, потому что ESLint не установлен в неполной папке `node_modules`. Это не доказывает наличие ошибки в исходниках, но и не позволяет заявить, что сборка чистая.
2. **Нет серверной части и аккаунтов.** Прогресс, имя и аватар хранятся только в текущем браузере. Очистка данных браузера или смена устройства может привести к потере прогресса. В приложении нет серверной авторизации или синхронизации.
3. **CSP задана через meta.** Это полезный дополнительный барьер, но полноценные заголовки безопасности (например, CSP, `X-Content-Type-Options`, `Permissions-Policy`, `Strict-Transport-Security`) должны задаваться на стороне хостинга. Для GitHub Pages часть таких заголовков нельзя настроить обычным файлом проекта.
4. **OCR загружает ресурсы извне.** Tesseract и языковые данные загружаются с CDN. Без интернета первое распознавание может быть недоступно, даже если интерфейс сайта открылся офлайн.
5. **Экзаменационный режим не является защищённой экзаменационной средой.** Таймер и проверки выполняются в браузере; пользователь технически может изменить состояние через инструменты разработчика.
6. **Мобильная и настольная адаптивность проверена по CSS и разметке, но не через реальный набор браузерных устройств.** Нужен отдельный визуальный прогон в Chrome, Safari iOS и Firefox с реальными размерами экранов, клавиатурой и сенсорным вводом.
7. **Учебное качество заданий требует отдельной редакторской вычитки.** Статический технический аудит не подтверждает безошибочность каждого правила, объяснения и соответствие каждого варианта актуальным демоверсиям ФИПИ.

## Что нужно для полного релизного допуска

- Выполнить `npm ci`, `npm run lint` и `npm run build` в чистой среде Node LTS.
- Прогнать приложение в Chrome/Firefox/Safari, проверить ширины 360, 390, 768, 1024 и 1440 px.
- Проверить клавиатурную навигацию, фокус, контраст, масштабирование текста и экранный диктор.
- Проверить все сценарии сохранения/восстановления профиля, сброса данных, завершения/прерывания экзамена, офлайн-режима и OCR.
- Провести отдельную методическую проверку банка вопросов и соответствия экзаменационных форматов актуальным материалам ФИПИ.
