# Подключение облачной синхронизации Русский Ясно v24

Облачный вход и синхронизация уже встроены в приложение, но для реальной работы владелец сайта должен создать собственный проект Supabase. Не используйте чужие ключи и никогда не вставляйте `service_role` key в сайт.

## 1. Создайте проект Supabase
1. Откройте https://supabase.com/ и создайте проект.
2. Сохраните пароль базы данных в надёжном месте.
3. В Project Settings → API скопируйте **Project URL** и **anon/public key**.

## 2. Создайте таблицу и политики доступа
1. В панели Supabase откройте SQL Editor.
2. Откройте файл `supabase/schema.sql` из этого архива.
3. Выполните SQL. Таблица `user_progress` будет защищена Row Level Security: пользователь может читать и изменять только строку со своим `auth.uid()`.

## 3. Настройте вход по электронной почте
В Authentication → Providers убедитесь, что Email включён. Настройте подтверждение электронной почты и разрешённые Redirect URLs под опубликованный адрес GitHub Pages. Для первого входа может потребоваться подтвердить почту.

## 4. Добавьте GitHub Secrets
В GitHub откройте репозиторий → Settings → Secrets and variables → Actions → New repository secret. Создайте два секрета:

- `VITE_SUPABASE_URL` — Project URL.
- `VITE_SUPABASE_ANON_KEY` — anon/public key.

Не создавайте секрет с `service_role` key. В клиентском приложении он не нужен и небезопасен.

## 5. Опубликуйте сайт
Отправьте файлы v24 в репозиторий и запустите GitHub Actions. Значения secrets попадут в сборку. После успешного деплоя в настройках сайта появится форма входа и регистрации.

## 6. Использование
1. Создайте аккаунт в приложении.
2. Подтвердите электронную почту, если это включено в Supabase.
3. Войдите на втором устройстве с тем же аккаунтом.
4. Если облачная копия уже существует, приложение предложит загрузить её или отправить локальные данные в облако.

## Важные ограничения
- Для синхронизации требуется интернет; офлайн-режим продолжает работать с локальными данными, а синхронизация возобновится при подключении.
- При первом входе на устройстве с существующим облачным профилем выберите источник данных внимательно. Перед первым переносом рекомендуется скачать локальную резервную копию.
- Если два устройства одновременно меняют профиль, применяется стратегия последнего сохранения целого профиля. Одновременное редактирование одного аккаунта на нескольких устройствах может привести к перезаписи более раннего изменения.
- Пароль аккаунта хранит и проверяет Supabase Auth. В приложении сохраняются только токены сессии.
- Проект не использует сервисный ключ на клиенте. Доступ к таблице ограничен политиками RLS.
- До настройки Supabase и добавления GitHub Secrets облачная синхронизация не активна.
